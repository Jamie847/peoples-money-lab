# 0.7.2 implementation progress — not frozen

The frozen [visible specification](../acceptance/0.7.2/SPECIFICATION.md) precedes implementation. This document is an implementation status report, not an amendment to that specification. No claim that all 48 cases are implemented or passed is made. These implementation-authored tests are not held-out evidence.

Use `OperatingEngine` from `src/engine072.mjs` to opt into the work in progress. The existing `Engine`, historical fixtures and archived evaluation remain unchanged. Run `npm test` for both engines, `npm run reproduce:072` for new diagnostic exports, and `npm run acceptance:072` for the [A01–A48 traceability map](../acceptance/0.7.2/TRACEABILITY.md). The map currently distinguishes 46 passed visible cases and two unresolved cases; these are not held-out results. `npm run reproduce` continues to reproduce the older baseline translation.

## Implemented components

The new engine separates auction awards from bidder settlement, applies a provisional 6% ceiling, distributes marginal ties with exact rational pro rata allocation, and exports settlement shortfalls and consecutive-auction flags. No retail settlement is admitted pending authorization-scope clarification. Each auction is explicitly finalized with `close_auction`; this prototype does not infer a settlement deadline or late-settlement policy.

Identified loan recoveries reconcile legal principal, residual, impairment, money destruction and financial loss-recovery income. A receipt must identify the loan, assert settlement, and have a unique receipt ID. Principal-only and residual-only recovery, including the R104/P0/U4 to R103/P0/U3 example, is implemented. Noncash possession does not reduce exposure. Collateral-sale net proceeds are supplied, reconciled and reported; this is not a collateral liquidation marketplace or expense-payment ledger. Within a partially impaired loan, recovery uses carrying value before releasing impairment; that accounting convention needs review before freeze.

The cash controller retains a rolling 60-business-day history, opens a single remedy at a violation, preserves its deadline, recomputes dividends from live settled R/T, and records late cure without erasing failure. Queued instructions do not post money. Quarter-end obligations retain their original deadline. Dividends require explicit settlement events; no simulator can guarantee an external payment occurred. Existing spending and redeemable-debt settlement count against the obligation exactly once. `schedule_tranches` records three identified monthly payments summing to the fixed allowance. `settle_tranche` actually credits a payment; the scheduler does not assert that an external bank paid it. `defer_tranche` is prospective and cannot recreate excess at quarter end, checked both when requested and against live settlement balances. Missed credits remain in history. Cross-month deferral of a monthly tranche remains explicitly unsupported rather than silently changing the three-month convention.

Boundary resets validate before changing path, residual and epoch. A staged reset blocks a new allowance until applied. Partial resets require the statute input to identify each loan and its residual reduction. Every amount must be within that loan's remaining residual and their sum must exactly match the declared new U; no pro rata, oldest-first or other allocation is inferred. Amounts are revalidated against settlement-time stocks and the new epoch bound before atomic application. Emergency recertification retains its original clock unless a complete qualifying calendar quarter was observed; persistent emergency loan tags remain in the register. A42 now explicitly tests attempted rollover/relabel as a non-bypass case: rejection preserves money, exposure, accounts, registers, epoch, allowance and clock; the outstanding tagged loan disqualifies the quarter and recertification cannot restart the hard stop. No new contractual-renewal policy or admitted renewal feature is introduced.

The observation helper retains the last verified target and previous available price-gap reading. It keeps an active brake target through a missing reading. Fixed allowances remain fixed. `ingest_release` records dated GDP/CPI-U/PCE release IDs, periods and revision status; `compute_quarter` selects permitted vintages and exports the exact selection. Releases must have been published strictly before the computation date. Price inputs use the latest three published months separately for each index, using only first releases; the explicit conversion-date bases rebase them to 100. Revisions are retained as provenance but excluded from price calculations.

The GDP fixture convention uses the ten annual periods ending before the annual update year, each identified as a third estimate. The annual slot is April 1, matching the first quarterly computation after late March. Revisions published before that slot can enter that annual update; later revisions wait for the next annual slot. If a required original third estimate is late, the previous verified trend carries until the first future quarterly computation with the complete annual set; a new first estimate cannot rewrite a fixed allowance. This annual-slot convention and the synthetic source records are explicit test inputs, not verification of agency releases. Observations published on the computation date are excluded because intraday publication timestamps are not implemented. Target roots and logarithms retain the existing binary64 convention; averages use rational arithmetic before conversion.

Supplying `verifiedTarget: true` with `begin_quarter` remains the explicit manual input route. Omitting a path uses the last target observation and rejects if none exists. Target verification and release provenance are scenario attestations, not authenticated live data feeds. Neither missing observations nor later ingested releases recalculate an already-open quarterly allowance.

Daily usage, weekly loan/overhang registers and immediate action records are exported with dates. Loan IDs must be synthetic/public-safe identifiers; this research prototype has no private identity store or privacy enforcement layer. Reports record overdue legal balances separately from residuals.

## Calendar and arithmetic

The bundled [calendar fixture](../fixtures/federal-calendar-2027.json) now covers published OPM Monday-Friday nationwide observed federal dates in 2027–2029, including December 31, 2027, the observed New Year holiday for 2028. Source: [OPM holiday schedule](https://www.opm.gov/policy-data-oversight/pay-leave/federal-holidays/). An explicitly supplied `holidays` array replaces this fixture. Other years, emergency closures and institutional applicability require an explicit reviewed calendar; the default is not a perpetual federal calendar.

Money and pro rata awards use rational amounts. Production indivisible payment-unit rounding is not resolved here. Bill-interest amounts are explicit contractual fixture inputs, not an implemented day-count accrual system.

## Outstanding decisions and work

- Recovery cash beyond principal/residual is rejected as POLICY_UNDEFINED. The interest/penalty/excess waterfall and its monetary categories are pending. A direct `payInterest` event is blocked in this engine to prevent bypassing the identified recovery path.
- Direct sales are rejected as POLICY_UNDEFINED until remaining authorization and overlapping windows are specified.
- Actual contractual renewals remain outside this engine. A42 tests the specified adversarial non-bypass requirement, not whether a renewal can be approved. The previous NOT_IMPLEMENTED classification unnecessarily required an admitted renewal lifecycle; the strengthened test and revised map record this scope correction without altering the frozen specification or introducing new contracts.
- Cross-month tranche deferral and broader multi-year 0.7.2 regression remain outside the completed visible cases. The current map is visible-case coverage, not a declaration that every operating path exists.
- Reproduction examples intentionally include partial schedules. Their overall report can be POLICY_UNDEFINED even when an individual component assertion passes. Do not convert an incomplete trace into a policy-compliance PASS.
- The implementation is not frozen. No unseen challenge has been supplied to or accessed by the implementer. Merge remains prohibited pending the separately run challenge against a later frozen commit.
