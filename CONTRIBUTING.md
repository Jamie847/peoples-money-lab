# Contributing

Counterexamples and missing assumptions are welcome. Include the commit, Node version, input events, command, observed result and expected accounting or policy result. Explain whether the expectation follows from a stated rule or is a proposed policy change. Keep private financial and personal information out of issues and fixtures.

Run `npm run check` before proposing a change. Add a regression test for a code bug. Do not resolve a policy gap by silently choosing a favorable rule. Separate policy alternatives into versioned configurations and disclose their consequences. Economic models, if later added, must state assumptions and compare alternatives; they are not implied by the present ledger.

A new dependency needs justification. Do not add credentials, network services or publication actions to the reproduction command. The project is a research prototype, not a financial product or production payment system.
